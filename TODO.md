```bash
corepack enable
pnpm install
docker compose up -d   # or point .env at your own local Postgres — see README
pnpm db:migrate
pnpm db:seed            # optional if DB already seeded
pnpm dev                # http://localhost:3000
```

Demo login: `sohel@example.com` / `password123`. Seeded children: Imran (PIN `1234`), Zara (PIN `5678`).

**Known local-dev gotcha:** if `next-auth` throws `MissingSecret` or `DATABASE_URL not found`, it's because Next.js only auto-loads `.env` from `apps/app/`, not the repo root. There should already be a symlink at `apps/app/.env -> ../../.env`; if it's missing, recreate it (`cd apps/app && ln -sf ../../.env .env`) and restart `next dev` (a full restart, not hot-reload — the Prisma client singleton bakes in env at first import).

**Known local-dev gotcha #2:** if using Postgres.app on macOS with `shared_preload_libraries=auth_permission_dialog`, connections to `localhost` can silently hang because that resolves to `::1` and Postgres.app's permission dialog gates new IPv6 client connections with a GUI prompt nothing automated can click. Use `127.0.0.1` explicitly in `DATABASE_URL` instead.

**Known local-dev gotcha #3 (AI features, when running `pnpm dev` from inside Claude Code):** the Claude Code desktop app exports `ANTHROPIC_BASE_URL=https://api.anthropic.com` into the shell it spawns — note the missing `/v1`. The Vercel AI SDK's Anthropic provider honours that env var and appends `/messages` to it, so every call goes to `https://api.anthropic.com/messages` and comes back **404 Not Found**. This breaks the morning digest and Word of the Day with a confusing error that looks like a bad API key or a bad model id. It is purely environmental — a normal terminal is unaffected. Fix: `unset ANTHROPIC_BASE_URL` before `pnpm dev` (or set it to `https://api.anthropic.com/v1`).

**Known local-dev gotcha #4:** `docker compose up -d` silently does nothing useful if another project's Postgres container already holds host port 5432 (`docker ps` will show it) — `household_postgres` then can't bind and stays stopped, and `pnpm db:migrate` fails with `P1000: Authentication failed` because it's actually talking to the *other* project's database. Check `lsof -nP -iTCP:5432 -sTCP:LISTEN` and `docker ps` before assuming credentials are wrong.

On spring-forward the result landed at 23:00 on the **previous calendar day**. This is session-7 code and predates the vocabulary feature — it affects chore `occurrenceDate`, "due today", and the digest, twice a year. Verified end-to-end against a throwaway empty database: the app build applied all 9 migrations and `VocabWord` existed afterward. Keeping the migration out of `packages/db#build` also means `typecheck`/`lint` still need `DATABASE_URL` only *resolvable*, not reachable.

- **Word of the Day error copy no longer names a cause.** It previously said the AI provider was misconfigured for *any* failure; the one time it mattered, the cause was a missing table. It now says "Today's word isn't ready yet" with a retry button, and prints no error text (the server masks it anyway).
- **Spaced repetition.**
  - Schema (migration `20260914001332_add_vocab_spaced_repetition`): `VocabReview` gains `easeFactor`, `intervalDays`, `repetitions`, `nextReviewAt`, `lastReviewedAt`, `reviewsPassed`, `lapses`, plus an index on `(userId, nextReviewAt)`. `nextReviewAt` is null until a word is first solved — an unsolved card isn't overdue, it simply hasn't entered the schedule.
  - `packages/domain/src/spacedRepetition.ts` holds the algorithm as pure functions with no clock and no timezone, so the curve can be reasoned about on its own. Verified numerically before wiring: perfect recall gives 1/6/16/45/131 days; a lapse after three passes resets to 1 day but keeps ease at 2.48 rather than starting over; a chronic failure floors at EF 1.3 instead of spiralling to a zero-day interval.
  - **`addDaysInTimezone()` (`packages/domain/src/timezone.ts`) exists because `dayStart + days * 86_400_000` is wrong across DST** — it lands an hour either side of local midnight, and an hour early snaps back to the previous calendar day, so a word scheduled for "6 days" would come due on day 5. It steps to midday of the target day first, then re-resolves midnight.
  - Router: `vocab.due` (the queue, batched at 5) and `vocab.answerReview`. Reviews are **reverse recall** — definition given, word to be picked, distractors drawn from the household's bank preferring the same level — which is both the harder retrieval direction and the reason no answer key has to ship: the card is identified by an opaque `reviewId` and graded server-side. A card with fewer than 3 available distractors is skipped rather than shown as a two-option coin flip. One attempt per review; one review per card per day (replaying a `reviewId` is rejected).
  - `stats` gained `reviewsDue`, `wordsInRotation`, `wordsMastered` (4+ consecutive passes, i.e. past the 16-day interval).
  - UI: `packages/ui/src/components/VocabReviewCard.tsx` + `apps/app/src/components/VocabReview.tsx`. Review sits above the new word on both the page and the dashboard, and `hideWhenEmpty` keeps it off the dashboard entirely on days with nothing due. A Junior-band word is reviewed using its 6-year-old definition, an ISEE one using the 10-year-old definition.
- **Bug found and fixed during verification: the daily points cap didn't bind on reviews at all.** `pointsEarnedToday()` summed `pointsAwarded` filtered by `readAt`, but the shortest review interval is one day, so a card being reviewed was *always* read on an earlier day — every review's points were attributed to a previous day and the 20/day cap capped nothing. Fixed with a per-row daily bucket (`dailyPoints` / `dailyPointsOn`, migration `20260914002110_add_vocab_daily_points_bucket`); every award now goes through `awardPoints()`, which rolls the bucket over on a new day. Verified by priming a user to 18/20 and reviewing: the award clamped from 3 to 2 and the day's total landed on exactly 20.
- **Local-dev note worth remembering:** Turbopack holds the generated Prisma client across a migration, so a dev server started *before* `prisma migrate dev` will keep querying with the old client and silently return wrong results (here: `dailyPoints` summing to 0 for ten minutes of confused debugging). Restart `next dev` after any migration. This is the same stale-workspace-module trap session 8 hit with `@household/domain`.

## What changed this session (session 8, 2026-09-13, NOT yet committed)

- **New feature: Word of the Day (educational / vocabulary).**
  - **Schema** (`packages/db/prisma/schema.prisma`, migration `20260913235707_add_vocab_word_of_the_day`): `VocabLevel` enum (`JUNIOR` | `ISEE`), `VocabWord` (the generated card — word, part of speech, both definitions, `synonyms String[]`, example sentence, quiz question/choices/answer index, `scheduledFor`, `generatedBy` provenance), and `VocabReview` (one row per word+person; read/quiz credit tracked separately on the same row).
    - `@@unique([householdId, level, scheduledFor])` is what makes the whole thing safe: Postgres doesn't collide NULLs, so a household holds exactly **one scheduled word per level per day** plus any number of NULL-`scheduledFor` **bonus** words. Two devices loading the dashboard in the same second race on that index; the loser catches `P2002` and reads back the winner's row instead of writing a second word for the day.
    - `@@unique([wordId, userId])` on `VocabReview` is what stops a kid re-reading one card for points — enforced by the index, not by a check-then-write.
  - **Generation** (`packages/ai/src/vocab.ts`): `generateVocabWord({ level, exclude })` via `generateObject`. Three things that were *empirically* necessary, not speculative — each one was a real observed failure during this session:
    1. **Synonyms came back as a comma-separated string**, not an array (Claude Haiku, on this exact prompt; small local Ollama models are far likelier to do it). Rejecting that outright means a blank card over a formatting quirk, so there are now two schemas in `packages/domain/src/schemas.ts`: `vocabWordWireSchema` (tolerant — synonyms may be `string[] | string`) is what the model generates against, then `normalizeVocabSynonyms()` splits it and `vocabWordContentSchema` (strict) validates before anything is stored.
    2. **Mode collapse**: asked three times at temperature 0.9, the model returned `reluctant` all three times — one of the prompt's own calibration anchors, despite being told not to pick from that list. The exclude list only says what *not* to say. Fixed by constraining the first letter to 4 randomly-drawn letters per call (`pickStartingLetters`), which breaks the mode reliably.
    3. **The model listed the word as its own synonym** ("reluctant" → `[unwilling, hesitant, reluctant]`). Prompt says not to; it did anyway; now filtered in code after parse.
    - Also: the answer's position in `quizChoices` is **re-shuffled server-side** in `generateAndStore` regardless of what the model returns — left alone it settles on index 0, which teaches kids to tap the first option without reading.
    - The `simpleDefinition` (6-year-old) prompt needed a worked before/after example plus an explicit self-check, because the model's first attempts were *more* complex than the 10-year-old definition, not less.
  - **Router** (`apps/app/src/server/trpc/routers/vocab.ts`): `today`, `bonus`, `generate`, `markRead`, `answerQuiz`, `stats`.
    - **The quiz answer key never leaves the server** until an attempt is submitted. `toClientWord()` strips `quizAnswerIndex` from every client-facing payload — otherwise the answer sits one devtools panel away from exactly the age group the ISEE band is aimed at. `answerQuiz` returns `correctIndex` only once the attempt is spent (on a correct answer, or after 2 wrong ones so a kid isn't left stuck).
    - `today` is a **query that can write** — unusual, but the dashboard card has to populate on mount with no interaction, and the write is idempotent per (household, level, day) by database constraint. A mutation fired on load would be a side effect on every dashboard render instead of one per day.
    - Generation retries up to 3× total, on **duplicates and on thrown errors alike** (a malformed structured-output response is a normal transient outcome); the last error is rethrown once the budget is spent, so a real misconfiguration still surfaces.
  - **RBAC** (`packages/domain/src/rbac.ts`): new `vocabWord` resource. `CHILD` gets `create`/`read`/`complete` — `create` meaning "generate another word at this level", which is the point of the feature, not authoring arbitrary content. Deliberately **not** in `OWNERSHIP_SCOPED`: the handlers always record against `ctx.actor.id` and never accept a target `userId`, so ownership is structural rather than checked.
  - **UI**: `packages/ui/src/components/WordOfTheDayCard.tsx` (presentational; level tabs optional so the same card renders inside the word-bank list), `apps/app/src/components/WordOfTheDay.tsx` (`ConnectedVocabCard` + `WordOfTheDay`), `apps/app/src/components/VocabPage.tsx`. Nav entries added to the web sidebar, mobile bottom nav, and `proxy.ts`'s protected prefixes.
  - Success/error tints are painted as **alpha over the themed surface** (`bg-emerald-500/10`) rather than fixed pale backgrounds (`bg-emerald-50`), since this project themes via CSS custom properties and deliberately has no per-component `dark:` variants — a fixed pale green stays light-only and glares on the dark palette.
  - Two `setState`-inside-`useEffect` patterns were replaced with derived state (quiz feedback keyed by `wordId`; `quizVisible = quizOpen || solved`) — `apps/app`'s eslint config flags the effect form, and it also lets one frame paint the previous card's selection against the new card's options.

## Tech debt / follow-ups noticed during Milestone 1

None of these block M2, but worth fixing opportunistically:

- **Word of the Day has no admin/curation surface.** Words are generated and shown; a parent can't veto one, pin one, or pre-load a list for an upcoming test. There's also no history view per child beyond the aggregate `stats` counters, and no streak tracking. Worth revisiting once it's been used for a few weeks.
- ~~**Vocabulary daily point caps are keyed on `VocabReview.readAt`.**~~ Fixed in session 9 — it turned out to be worse than a boundary nit (reviews bypassed the cap entirely); now bucketed by the day points were actually earned.
- **`vocab.today` generates on a GET.** Documented and safe (idempotent by unique index), but it does mean the first dashboard load of the day pays an LLM round trip inline, and the `/display` kiosk will trigger generation unattended. A warm-ahead cron would be the fix if the latency ever shows.
- **Test coverage is one package deep.** Session 9 added Vitest and covered `packages/domain`'s scheduler and timezone math, but RBAC correctness is security-sensitive and still untested: the `rbac.ts` capability table and the tRPC ownership checks (`task.setCompletion`, `rewardRedemption.create`) are the obvious next targets, followed by the household-scoping middleware. No integration or browser-level testing exists.
- **Row-level security not applied.** Household scoping is enforced entirely in the tRPC middleware layer (`apps/app/src/server/trpc/trpc.ts`). Fine for now; Postgres RLS was flagged as Phase 2+ hardening in the design doc.
- **`packages/domain`, `packages/ui`, `packages/db` have no lint script**, only `apps/app` does. Not urgent since they're pure TS with no framework-specific rules, but worth adding eslint configs if the packages grow.
- **Kiosk layout's `ProfileSwitcher`** is fixed at `bottom-4 right-4` and can overlap dashboard content on short viewports — fine on an actual large kiosk display, worth revisiting once real device sizes are known.
- A stray root `package-lock.json` was found and removed during Milestone 1 (this is a pnpm-only repo). If it reappears, something (possibly an IDE) is running plain `npm install` — worth checking IDE Node.js integration settings.
- **`packages/db/prisma/seed.ts` isn't safely re-runnable** against a non-empty DB — `prisma.user.create` hard-fails on the `email` unique constraint the moment the demo household already exists. Fine for a truly fresh DB (`docker compose up -d` + first-ever `pnpm db:migrate && pnpm db:seed`), but breaks the "just re-run the resume command block" story for anyone iterating on seed data. Worth making idempotent (upsert by email, or a guard at the top that bails if the demo household already exists) before it grows further.
- **Meal-plan grocery-list generation does no unit conversion or smart merging** — duplicate ingredients across recipes are merged by exact lowercased name only, and quantities are concatenated as text (e.g. "2 cups + 1 tbsp"), left for the shopper to reconcile. Fine for MVP; a real implementation would need a unit-aware quantity parser.
- **Two-way Google write-back only pushes to an event's existing assignees' calendars** — there's no "always push to the creator" fallback, so an event with zero assignees never mirrors anywhere even if the creator has Google connected. Revisit if that turns out to be surprising in practice.
- **Concurrent-session file locking on Windows**: `prisma generate` fails with `EPERM ... query_engine-windows.dll.node` if another `next dev` process (this session's own or a different Claude Code session in the same repo) has the Prisma client DLL loaded. No code fix needed — just something to know when working in this repo from multiple sessions/terminals at once. See "What changed this session (session 2)" for how this was handled.
